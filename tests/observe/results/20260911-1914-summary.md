# DSCA-4 observation run

- Window: 2h0m1s, scale 1000 across 20 services, churn 5.0%/min
- OBS_BOUND = max(SLO 10s, push-interval 60s) = 1m0s; reconcile-source nacos

**Scope of this window — read before quoting.** This is the SUSTAINED
window: 2h of continuous 5%/min create-before-delete churn at 1000
instances, with the per-tick consistency verdict as the criterion. The
§4.2 OBS_BURSTS shapes (the 100-in-1s storm + the 200-instance batches at
25%/50%/75%) are NOT part of this window — they are exercised by the
complementary burst-augmented window (see the 25m burst run's summary in
this directory). The two windows together cover §5.2's Scale bullet: this
one proves duration+sustained-churn consistency; the burst run proves the
burst shapes and their convergence bounds. The ecs/consul leg is likewise
not part of this stack: the contract (dsca-4 §8) keeps consul at soak
scale, and this run's `--providers k8s` scope is the declared scale axis.

**Run provenance note.** Third attempt. Attempt 1 (16:59) ended VOID: at
~46m the host's colima port-forward tunnel for 28848 died under host
memory pressure (swap 10.7G/11.2G used; the nacos container itself stayed
healthy — the observation correctly reported OBSERR, never false
divergence, then a DIVERGENT catch-up backlog while the retry queue
drained ~2000 entries). The run was stopped ~61m later, after the drain
completed, so the post-incident behavior was observed rather than
truncated. Attempt 2 (18:04) was externally killed at ~59m/355 ticks with
zero divergent and zero OBSERR ticks. This attempt 3 (19:14) ran the full
window. The per-tick JSONL was unlinked mid-run by an operator cleanup
while the test process held its fd open; the 721 window ticks were
reconstructed verbatim from the harness log's per-tick lines (the
reconstruction script verified every invariant: verdict, both sides'
counts, drops — 0 violations; the log itself is preserved at
evidence/20260911-1914-harness.log.txt). The summary JSON/MD were written
fresh by the run itself. One reconstruction scope note: the window JSONL
and verdict deliberately exclude the cold-attach pre-window tick-0 lines
(1 CONSISTENT + 3 DIVERGENT + 1 CONSISTENT while the initial 1000-pod
wave propagated — visible in the harness log at 19:18:20-19:19:05);
the 721 window ticks begin at tick 1, after the cold-attach convergence
gate.

**Latency window note.** The e2e histogram's observation count (n=14,958)
includes ~1,900 pre-window events (the cold attach's 1000-pod wave and
the child's startup): the percentile columns therefore describe the
whole child lifetime up to the final scrape, not strictly the 2h window.
The window-only population differs only by the cold-attach wave, whose
latencies land in the same seconds-bucket range as the churn waves.

**Churn-rate gate semantics.** The window executed 5,983 create+delete
pairs = 49.85 instances/min against the nominal 50/min (5% of 1000). The
§5.2 gate counts instance CHANGES (the contract's ">= 50 instance changes
per minute", both directions of each replacement), so 49.85 counts each
create AND each delete — i.e. 99.7 change-events/min, comfortably past
the gate; the deficit vs 50 pairs/min is the sub-tick churn fraction
accumulator's rounding at the 20s cadence (16.67 pairs/tick exact).
